# 阶段 2Z：直接槽引用类型检查

## 结果与范围

实现 `10 vm_checkIsRefType`：在普通函数的当前调用帧内检查指定槽的引用形态，压入独立 Int 0/1，不消费原槽。现为 **70 种限定操作码**，主语料交集68种，缺 `05/06/17/35/36` 五种。动态索引版本 `11`、初始化/构造/回滚及默认表达式执行仍排除；不新增公共API、Value类型、依赖或unsafe。

新增10项VM集成测试、5项内部测试，合计 **359项Rust测试**（27单元、23解析/CLI、309 VM）。所有执行程序均为合成输入；CLI仍只读检查制品。没有运行参考ELF、启动脚本或业务字节码，也不据11处静态出现次数宣称业务可执行。

原版栈向低地址增长。若容量为C，Rust已用长度为N，则原版sp=C−N；Rust帧bp对应原版参数0位置C−bp。因此原版 `native_bp+a` 对应Rust `bp−1−a`。原版 `a<argNum && native_bp+a>=sp` 对应当前 `slot()` 的参数上界和压入前实际栈边界。非负索引选择实际存在的参数；负索引可以选择已分配局部和计算槽，而不只受声明local_count限制。越界或未分配返回0，不能通过大正索引窥读调用者前缀。

这些是静态观察及布局对应推导，不是原版动态差分。未覆盖无调用帧、全局/宿主回调/JIT以及损坏原生帧的整数算术或分配失败恢复。

## Rust行为与失败规则

`check_reference_type` 先拒绝生命周期任务，再检查值栈容量，通过当前帧 `slot()` 在压入前计算位置。仅匹配 `StackEntry::Reference`，不调用 `value()`、`resolve()`、`copy_value()` 或引用预留。普通值和隐藏循环控制Cell均返回0；失效、只读或指向已退出帧的Reference仍返回1。默认值补齐后的有效argc/bp、可变参数及既有继承/跨对象帧布局沿用当前实现。

判定不解引用、不规范化失效Object、不复制引用lease，也不触发引用配额扫描。引用配额已经耗尽时仍可检查已有槽；结果自身仍占一个值栈槽并需分配Cell。容量失败返回Limit，原槽与操作数保留；分配前不改源，Cell ID消耗和标准库OOM不提供回滚保证。错误定位沿用run()的source、对象、程序、函数、PC及offset，PC遵循既有先前进再执行规则。

准备阶段拒绝初始化节点和默认表达式中的10；普通初始化/构造/回滚辅助函数执行时也明确返回UnsupportedFeature。之后仍进入既有任务清理和构造回滚流程，不能把指令局部不修改源解释为整个任务状态不变。11继续不在支持表中；也不扩展引用创建、传参、逃逸或返回规则。

每条10消耗一个指令预算；零预算没有分配或栈变化。检查错误不标记RuntimeFaultSite，栈限额错误即使处于catch内也仍为终止错误，原有数值catch白名单不变。

## 语料与验证

[只读重算](stage2z-evidence/corpus-summary.json)确认7,159程序、101,592普通函数、6,474,773指令中共有11条10，全部在普通函数内：AAA7条、GS4条。par16=0/2/4/5分别出现1/4/2/4次，par8均为0。全部成员、函数、PC和解压后成员内偏移见[发生位置](stage2z-evidence/corpus-occurrences.json)，4个分组样例和方法保存在同目录。

语料记录原始原型数量和参数flag，不据此判断运行时引用或可达性。负索引、极值、非零par8等仅有原生路径依据及合成测试，不能声称在真实业务中已执行。

新增集成测试覆盖普通值/引用参数、嵌套转发、可选缺省/默认补齐/可变参数、局部/计算槽、预算、容量错误、继承与跨对象引用、生命周期清理及11拒绝。内部测试覆盖失效/只读引用、隐藏循环、失效对象不规范化、满引用配额不增加lease、有效帧边界和失败不修改源。

debug/release测试、fmt、严格clippy、证据校验与损坏测试、语料重算、矩阵规则测试及全量语料比较结果见[阶段验证](stage2z-validation.json)，[当前矩阵](stage2z-evidence/matrix.md)保持所有支持行为为bounded。全量比较仅核对结构与哈希，12包/7,159程序/36个原始制品不变，仍明确报告唯一已知DBA LZSS异常。
