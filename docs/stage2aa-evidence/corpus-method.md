# Stage 2AA static global namespace audit

`python3 docs/stage2aa-evidence/analyze_corpus.py` verifies retained artifacts without writing. Pass `--write` explicitly to regenerate. Run synthetic checks with `python3 -m unittest discover -s docs/stage2aa-evidence -p test_analyze_corpus.py`.

The input is the existing decoded Main Magic559 corpus, not newly executed programs. Input and compatibility-baseline SHA-256 values are embedded in the summary. The scan checks every retained init node and ordinary/hidden function node, validates signed i16 `a`, signed i8 `b`, opcode and segment offsets, and reconciles program/function/instruction and relevant opcode counts with the compatibility baseline. Member node offsets are uncompressed member-relative `nodes_offset + 4*pc`. No reference executable, bootstrap script, or business bytecode is run.

All 17,500 `35`, 3,929 `36`, and 25,574 global-bit `07` occurrences are retained in deterministic `corpus-occurrences.json.gz` (47,003 rows). The summary also counts all 126,466 `07` and 143,520 `06` nodes, preserving raw operand combinations and unsigned flag modes separately. `07` decodes bit 7 as global dispatch, bits 0..5 as argument count and retains bit 6 as other metadata; it does not infer runtime argument types, reachability or flag meaning beyond those fields. Examples are the first retained occurrence for each opcode/raw unsigned mode/context, with a two-node neighborhood (17 representatives).

Each program maps to a global unit only when the first source-path component has exactly one `mode=global` candidate. This corpus has exactly five such server prefixes and no ambiguous binding. This source-name grouping is a static assessment, not evidence of runtime registration or a package trust boundary. All observed `35/36` signed indices are within the matching global unit's `[0,max_vars)`; per-program bounds counts and every index remain recorded.

`global-units.json` preserves source/member hash, function base, efun count, max vars, the variable-descriptor list, max functions, every ordinary function slot/name/offset and the raw DLT descriptors plus attribute/index histogram. All five variable-descriptor lists are empty even though max vars are 105 (aaa), 102 (ccs), 98 (csa/dba), and 359 (gs). DLT records therefore remain raw evidence; their `index` field is not substituted for a global variable slot or a function slot. No new variable names or storage layout are inferred.

All five global units have efuns_count=559 and function_base=572. Every `06` operand is in the numeric `[0,559)` efun range. Of global-bit `07`, 25,524 indices lie in the matching module's `[function_base,max_functions)` interval. The other 50 are pre-module slots in `[559,572)`: slot 559 occurs 5 times, 564 occurs 10, 569 occurs 10 and 570 occurs 25. None is negative, in the efun numeric range, or at/above max_functions. These pre-module calls are **not classified as invalid**: the interval describes module-defined functions only, and the native global table may contain previously registered functions. The corpus alone does not establish their names or runtime targets. Per-server slot counts and numeric namespace classifications are retained without conflating efun numbering, global function slots and global variable indices.

Synthetic checks cover malformed nodes, signed operand overflow and booleans, invalid offsets/node lists, negative/out-of-range indices, global/other flag separation, non-global calls, duplicate sources, ambiguous global bindings, invalid inventory bounds, and deterministic gzip output. Static unknowns include runtime value types, successful initialization, callable targets outside saved module-defined slots, and actual execution frequency.
