# 结果与限制

完整有限域的 debug/release 差分没有发现新的生产偏差，生产运行时没有修改。两份准备共享一个实际槽时只保留该槽已有的 owner；移除 root 后，最后计划退出才可能销毁槽。首次提交即使写回相同值，也使观察该目的版本的另一个计划失效；首次 abort 不制造这类版本变化。提交失败释放自己的准备责任，不撤销另一个事务或此前成功结果。

两份 Function 预留分别取得一个 creator 责任，第二份配额拒绝保留第一份；creator invalid 后一份发布失败只归还自己。两份执行准备可共同保活 Pending，commit 只转移租约，最后 installed/prospective 租约退出才使用预留普通单位入队一次。失败点及借用对照、部分维护和正常库嵌套帧回归分别支持这些受限路径。

新增工具开发时纠正了三类自身问题：make 替换 root 需要新的稳定 Cell 身份，不能覆盖旧 Weak 标签；Mapping／Function 物理析构可再次失效已清空成员的版本，应与语义 owner 释放分别建模；未发布输出隔离须同时检查槽地址和 header 标签。这些属于新夹具／参考层接入修正，不是原生产缺陷。最终 worker 重新执行后观察与已保存的合法域逐字节一致，源码指纹绑定在命令日志。

核心 54,816 条 setup 拒绝单独记账；A/B 成功次数排除 setup 的 Z 初始化。预留失败后继续执行的缺失令牌终结按测试协议 InvalidState 分类，不冒充公开 API 或原生行为。公开组只证明十种顺序／嵌套投影，内部同时在途准备不是公开并发能力。

范围仍是两个准备、确定的小图和指定干扰。任意数量事务、长操作序列、头循环、任意重入或线程没有由本批证明。元数据及物理析构版本规则包含具体实现细化，full_model_equivalence 和 native_equivalence_proven 保持 false。原始未发布 H/A 最终处置、原生退出进展、32 位执行和真实业务启动仍待独立工作，20 项 native unknown 不提升。
