# 后续Rust实施规格与前置门槛

本页是2AR基于证据给出的后续约束，**非标量捕获尚不标为可直接实施**。2AR不修改Rust/API/依赖。F01—F23及C01—C51的静态期望不是原版运行oracle；以下“保持/拒绝/必须”是拟议Rust政策，除明确引用原生结论外不声称等价。

## 顺序与确定边界

1. **先做源复制与语义所有权设计闭合（下一批2AS）**。保持现有标量白名单及所有公开入口，盘点全部Function创建/保存/加载/参数/返回/Host opaque传递/快照接点，定义哪些形成VM语义持有者，哪些只是宿主观察。不得按Rc::strong_count选择原生唯一分支。设计必须同时锁定容器成员写入形成Function→容器→Function图的检测；仅现有容器深度检查不足，因为此前捕获只含标量。
2. **随后才考虑受限无环Array/Mapping捕获**。建立与展开保持浅header共享，不能深复制或提前递归规范化成员；读取具体成员时再执行该接点源清理。保留Mapping/Array不同最后header语义，保留全部原有键/属性/循环绑定限制。
3. **直接Object/Function捕获单列后续批次**。必须闭合唯一move与共享COPY的失效源区别、creator与被捕获owner分离、ref/execRef删除及失败最终释放。不能因原生建立循环只拒绝tag8就一次开放全部Value。

## 最小内部表示与数据流要求

后续源复制接口不能只返回`Value`。采用私有“复制计划”结果，至少表达目标值与待规范化的实际源Cell；为多源接点收集一组更新。调用方在结果Cell/栈/帧等可报告资源预检后，先取得全部必要借用，再提交源更新和目标/PC变化。禁止先改某个源，再因后续参数/借用失败留下未说明的部分提交；临时Cell ID不要求回滚，宿主不可恢复OOM继续不作保证。

该计划只服务真正COPY接点：普通局部/Object/Global读取、显式解引用、成员读取，以及按语义共享头展开的捕获。raw-move接点（17建立、唯一head展开、选定非const普通返回）不能顺手调用统一规范化。Array/Mapping header COPY不递归改成员；owner-null Function不因None失效，foreign origin先执行Rust隔离检查。

捕获源若需要被共享COPY改写，当前不可变`Vec<Value>`不够表达该语义；应设计私有稳定捕获槽。稳定槽不赋予捕获Reference逃逸能力。表示设计必须证明最终头释放的槽/载荷清理、与公开FunctionValue身份比较/Debug隐藏捕获的兼容，以及不因宿主读快照改变分支。**在2AS给出完整持有者生命周期和迁移方案前，不选定计数实现、不开放类型。**

## 图、资源和失败政策

首批只允许已验证无环图；图验证需遍历Function捕获边，考虑构造、参数、Host结果、成员写、Mapping循环输出及重绑。Function仍按头身份相等；图校验不得改成深相等。检测到循环、超过既有限额、未知属性/能力或借用冲突必须在可见修改前报明确错误，不以跳过Function边处理。

继续使用现有VmLimits、VmErrorKind、origin与单次同步Host规则，不新增RuntimeFaultSite，不扩大catch来源。现有旧准备入口保持原能力集合；新增捕获入口/API是否必要属于2AS必须闭合的设计项，本批不擅自将全部旧入口升级。

Rust继续保持成功发布前预检和受控失败政策；与原生先消费目标、逐参转换、COPY可修改共享捕获的顺序差异逐项登记。有效原生script catch可清理栈，但不会回滚此前源变化；不因此宣称Rust所有预检行为已原生等价。无catch、其他线程、JIT/callback、未发布头及复杂删除/重入继续排除。

## 必须满足的未来验收

- 源复制/移动接点表逐项有测试：源Cell/alias结果、header共享、owner-null/已删除/foreign-origin及返回不误规范化。
- 原生语义唯一/共享条件能通过明确VM持有者构造；增加宿主clone、Debug/stack快照后不改变VM路径。若做不到，非标量捕获保持关闭。
- Array/Mapping捕获通过无环图检测；容器成员写Function、嵌套Function/容器、Host返回、循环三元输出均不能产生未检测环；拒绝路径保持原对象、游标、目标槽和操作数。
- 捕获创建、展开、最后释放、参数错误和数值catch解栈覆盖载荷最终释放，不重复释放；保留成员Ref下Array/Mapping差异。
- 零预算不分配/不改源；17发布后、05用户callee入口或Host单步完成后可暂停；失败不重放Host副作用。
- 运行原558项debug/release回归、fmt、严格Clippy及新场景。具体新增测试数由实际交付统计，不预造通过数量。
