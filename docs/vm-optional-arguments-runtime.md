# 阶段 2J：默认参数与可变参数的受限运行时

## 总体结果

Rust VM 已支持当前对象内的可选 mixed 参数、线性默认表达式和可变参数。新增 `47` 参数重排、`34` 参数数量、`15` 参数数组，限定 opcode 集合由 52 增至 **55**。验证只执行 Rust 测试、人工构造程序和只读语料解析，没有执行参考二进制、启动脚本或业务字节码。

原生格式和语义依据为[阶段 2I 静态分析](vm-optional-arguments.md)及其[REA/Ghidra 证据](vm-optional-arguments-evidence/index.md)。本轮没有新开 Ghidra 会话，没有新增依赖或 unsafe。继承、跨对象/全局调用、atomic、const 和原生异常恢复仍未实现。

## 一、接口与支持范围

公共 `program::Argument` 新增 `default_action_count: i16`，从原始20字节描述符偏移10读取，JSON 输出增加同名字段。使用结构体字面量构造 Argument 的调用方需要补充该字段；`Vm::start`、公共 Value 和 Cargo 依赖保持不变。

PreparedFunction 分开保存 min/max、variadic 及默认入口布局，Frame.argc 表示有效槽数。新开放的非固定/可变函数须有合法 `0f → 默认段及可选47 → 1b` 入口；min/max 在0..127、描述符数等于max，参数索引连续，默认长度非负。已有固定参数路径保留；脱离合法默认入口的47不允许执行。

默认表达式仅开放 `3b/3c/3f/40/42/3d/16/18`，即整数/实数/字符串/Undefined、对象变量读取和容器字面量。每段静态检查不能消耗前段或参数槽，且净产生一个普通值；默认段调用、分支及其他操作码明确拒绝。未知参数位、空实现、继承、atomic 和 const 继续报错。

## 二、调用与默认求值

| 阶段 | 实现行为 |
|---|---|
| start/07 | 检查至少min、非variadic不超过max；检查引用绑定及省略形参，成功后建立帧 |
| 0f | 原子检查已提供的描述符参数；按默认指令累计长度确定入口 |
| 默认段 | 逐条执行，正常消耗预算；不自动补齐无默认mixed |
| 47 | 检查结果数量和类型形态，重排已有StackEntry，更新bp/argc |
| 1b | 入口状态完成后才分配局部槽 |
| 49 | 按更新后的有效argc清理，普通返回值规则保持不变 |

`start` 的参数数量错误现在立即返回 `ArgumentCount`，不会等到0f；失败保留此前完成/失败执行的状态。包含引用形参的根入口仍需内部包装调用，不开放宿主引用注入。

省略区间中的显式默认值必须从第一个缺失位置连续产生，尾部可以保留无默认mixed。中间零默认空洞或省略引用形参返回 `UnsupportedFeature`。无默认且缺失的typed参数属于非法元数据。缺失mixed没有槽位：37返回Undefined，39/4d报Bounds；argc不扩大到max。

多个默认值必须保持声明顺序。Rust栈向上增长，47使用“先逆序新增默认结果，再将其移至原实参前”的变换：

```text
原栈：[调用者前缀, arg1, arg0, default2, default3]
新栈：[调用者前缀, default3, default2, arg1, arg0]
```

该步骤仅移动现有槽，保留Cell身份、引用拥有者、readonly、成员种类和额度凭据。47不会再次按声明类型转换默认结果；默认值类型由生成它的字节码决定，这与原生路径一致。

若 `argc<max`，但所有显式默认值已经提供而仅缺尾部mixed，仍按原生入口经过一次零新增结果的47，再进入1b；不会跳过这条指令的预算消耗。无默认段时直接进入1b。

新入口使用私有状态区分检查、默认求值、待进入和函数体。准备阶段拒绝主体中的重复0f/47/1b，以及跳回初始化区域的分支；运行时也验证状态和47的结果数量，阻止绕过或重复初始化。预算可在每个入口阶段暂停和恢复。

## 三、可变参数与失败语义

可变标志允许超过max的实参保留为独立槽位；额外参数只能是普通Value，不自动形成尾部数组，也不按不存在的描述符进行类型检查。普通mixed形参仍拒绝Reference。

- `34` 返回当前Frame.argc。默认重排后包含实际生成的默认槽，不包括未补槽的mixed；Rust根入口是脚本帧，因此也返回其argc。
- `15` 显式生成全部有效参数的普通数组，顺序为arg0、arg1……；引用参数读取目标值，容器保留共享身份。
- 参数数组先完成读取、容器及结果槽分配和限制检查，再批量提交引用目标的死对象归一化及结果；失败不部分清理源Cell。普通非引用复制仍沿用现有策略，不扩大隐式源清理范围。

07/0f/47保持步骤级原子性，已完成的默认求值或函数体写入不回滚。类型检查失败不会提交前面参数的数值转换。错误保留源、函数、PC和偏移；终止帧与引用在下一次成功start或VM销毁时释放，不模拟原生catch/longjmp恢复。

原子类型检查、普通mixed拒绝Reference、根入口语义和普通死对象复制仍有已披露的原生兼容差异；55条限定指令不代表完整解释器或可运行服务端。

## 四、验证结果

`cargo test --locked`：**150项通过**，其中库单元测试7、解析/加载器测试23、合成VM测试120；相较阶段2H基线新增18项测试。覆盖全部/部分缺省、默认值顺序、数值metadata、字符串、容器、mixed不补槽、可变实参访问、34/15、引用身份、返回清理、预算暂停、对象删除、资源限制、原子失败及非法入口拒绝。

加载器全量比较也通过：12个PAK、9,527个成员、7,159个程序、9,933条继承记录均与既有基线一致。新字段额外与独立Python解压器直接读取的原始记录比较，覆盖**358,411个参数及局部变量记录**；预期不依赖Rust输出的raw_hex。36个原始文件哈希保持不变。

已知 `dba/pack_data/etc.pak/etc` 解压异常继续被明确报告，比较器只在确认该唯一既有异常时通过；没有隐藏新增错误。全量比较只运行新写的rml32-inspect及静态解码，不解释执行业务指令。

```sh
cargo test --locked
cargo fmt --check
cargo clippy --locked --all-targets -- -D warnings
cargo build --locked --bin rml32-inspect
python3 tests/compare_corpus.py --report target/stage2j-corpus-validation.json
```

验证命令、输入保护及文件哈希见[stage2j-validation.json](stage2j-validation.json)。阶段2I证据保持不变。下一步仍需独立推进默认表达式中的调用/控制流、继承与跨对象调用、efun及异常恢复；本轮没有测得业务字节码的可执行覆盖率。
