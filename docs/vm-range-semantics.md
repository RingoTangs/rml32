## 原生观察

### 操作数与区间

栈从旧到新为 **source、begin、end**；原版栈向低地址增长，`vm_sp` 是 end，`vm_sp+1` 是 begin，`vm_sp+2` 是 source。先转换 begin 的 Real，再转换 end 的 Real，之后检查两者为 Int；失败调用 `vm_error("Index should be integer.\n")`。转换调用位于 `0x0808fed2/0x0808fef2`，会原地修改端点类型和值。

端点闭区间，mode 的低两位独立作用：

| mode | begin | end |
|---|---|---|
| 0 | 绝对索引 | 绝对索引 |
| 1 | 绝对索引 | 从尾部计数 |
| 2 | 从尾部计数 | 绝对索引 |
| 3 | 从尾部计数 | 从尾部计数 |

设源长度为 L，尾部端点先将输入 x 下限置 1，再求 `L-max(x,1)`。因此尾部的 0 或负数也表示最后一个位置。之后将 begin 下限裁剪为 0，end 上限裁剪为 L−1；若 begin>end，结果为空；否则长度为 end−begin+1。绝对负数不会自动解释为倒数索引。Array 空区间分支额外把 begin 置为 end+1，确保复制循环次数为零。

例如 L=5：mode0 `[1..3]` 取 3 项；mode1 `[1..1]` 取索引 1 至 4；mode3 `[3..1]` 取索引 2 至 4。mode2 在当前语料未出现，但原生三条类型路径都有独立位测试，设计应测试该组合。函数内未见高位拒绝；受限 Rust 将主动拒绝 mode0..3 之外的编码，不声称非法模式等价。

### 类型、复制与释放

| source tag | 原生路径 | 关键位置 |
|---|---|---|
| String 4 | 新建 String，非空范围 `strncpy`，记录完整范围长度，补末尾终止符；空范围压入空共享字符串 | `0x0808fdac`、`0x0808ffd2`、`0x0808fff7`、`0x08090003` |
| Buffer 5 | 新建 Buffer，非空范围 `memcpy`，消费 3 个操作数再压入 Buffer | `0x0808fe44`、`0x08090024` |
| Array 6 | 先消费 2 个端点，新建数组头与元素槽，逐元素 `vm_copyValue`，释放旧数组引用并替换 source 槽指针 | `0x0808ff08`、`0x0808ff42`、`0x0808ff6e`、`0x0808ffa4`、`0x0808ffb9`、`0x0808ffc4` |
| Mapping 7 / 其他 | 明确进入错误路径；不自动解引用 source | `0x08090040`、`0x0808fd87` |

String 使用的是 `strncpy` 而非 `memcpy`：在**选中范围**内遇到 NUL 后，剩余结果字节补零，逻辑长度不缩短。源 `[0x41,0,0x42,0xff]` 的 `[0..3]` 得到 `[0x41,0,0,0]`；`[2..3]` 得到 `[0x42,0xff]`。该结论依赖被调用导入函数的标准契约，未做原版运行对照。非 UTF-8 字节不作字符解码。

Array 复制保持元素顺序。新非空数组有独立顶层槽；嵌套 Array/Mapping 仅增加共享引用。`vm_allocateEmptyArray(0)` 复用 `_nullArray`，不能声称原版所有空结果都有新身份。`vm_copyValue` 对选中的已销毁 Object 会清理**源元素槽**并复制 Undefined；仅规范化所选的直接元素，不递归遍历嵌套容器。其他仍有源数组别名时也能观察到此更新。

原生失败状态不能统一称为原子：实数端点在后续类型错误前可能已转换，Array 在分配前已弹出端点。分配/释放助手、原生 catch 与进程终止的完整组合未在本批恢复。保留这些限制，不把成功结果规则扩大为所有失败路径的等价承诺。

`46` 的无条件错误为 `Can't modify range of a value.`；下一批仅设计查询，不实现范围引用或范围写入。

## 下一批受限实现规格（尚未实施）

### 接口与准备阶段

- 不新增公共 `Range` 类型或公共构造器；结果直接为现有 `Value::Bytes/Array`。未来仅在实现通过后将 `45` 加入支持表。
- `prepared::instructions` 校验 mode 为 0..3；par8 按原生单参数分派忽略并保留原始诊断信息。初始化节点和线性默认表达式白名单仍不开放 `45`，避免同时扩展生命周期和默认表达式执行范围。
- 本批后续实现限普通函数，包括已支持的继承与跨对象调用。除初始化准备阶段拒绝外，运行时也须在 initialization/construction 任务中拒绝 `45` 为 `UnsupportedFeature`，防止普通 create/destruct 辅助函数绕过生命周期边界。直接 Reference source/端点沿用 `value()` 的 `UnsupportedFeature`；Buffer、Mapping、函数值及其他不支持的值类型返回 `UnsupportedType`，不悄悄解引用或转换。

### 计算与提交

- `Vm::step_instruction` 先 `need(3)`，通过 `value()` 读取 source/begin/end。端点只接受 Int/Real；转换复用现有数值策略（截断，NaN/无穷/超范围为 i32::MIN），不新增强制类型转换。
- 独立范围辅助函数执行上述闭区间规则，不复用单成员 `array_index` 的越界拒绝规则；用 i64 临时算术避免宿主溢出。源长度超过 i32::MAX 返回 `Limit`。合法越界通过裁剪得到结果，不报 Bounds。
- Bytes 实现选中区间内 NUL 后补零，不使用 UTF-8 或普通切片复制替代；结果最大 65,536 字节，超过返回 `Limit`。该上限是新受限策略，非原版限制；不为此新增 VmLimits 字段。
- Array 用现有 `Value::array` 建立新顶层槽，沿用 65,536 项/深度 64/无环限制；嵌套容器共享。空结果沿用 Rust 的新空数组身份，明确与原生共享空头的差异。
- 收集所选源 Cell、读取值及已销毁 Object 更新，先分配结果，再通过 `Cell::replace_batch` 一次提交所选源槽规范化与 source 栈 Cell 替换；按 Cell ID 去重，成功后移除两个端点。只更新选中直接元素，不清理未选中或嵌套对象。
- 指令提交前失败不改变输入值、源数组与引用配额；先完成所有可失败检查和受控分配，再提交。这是指令局部保证，初始化/构造任务拒绝后的既有错误清理与回滚仍可能释放任务栈、帧及对象。Rust 标准库 OOM 终止不纳入可恢复分配保证，Cell ID 消耗不回滚。相较原生提前转换/弹栈，这是明确的 Rust 安全策略。

### 错误、预算与上下文

- 模式错误为准备阶段 `UnsupportedFeature`；不支持的值类型为 `UnsupportedType`，Reference 为 `UnsupportedFeature`，计算栈不足为 `StackUnderflow`，资源超限为 `Limit`，借用冲突沿用 `InvalidState`。保留现有诊断补全规则：source、程序、对象、函数、初始化/生命周期、PC、成员内指令 offset。原操作数通过该位置查回保留的 Instruction，不新增 VmError 操作数字段。
- 不新增 `RuntimeFaultSite`；所有范围错误仍不可捕获，周围已有 catch 不改变这一点。
- 一条范围指令消耗一个预算，不在复制中间暂停；零预算无分配/规范化。继承与跨对象调用沿用当前帧的程序池和对象上下文，操作完成不改这些上下文。

### 后续实现验收用例

1. mode0..3 分别覆盖空源、单元素、全范围、反向范围、负数、超界、尾部0/负数以及 i32::MIN/MAX；确认裁剪和闭区间。
2. 实数小数、±0、NaN、±无穷及转换边界，混合 Int/Real，错误类型与引用不被接受；检查失败诊断和输入保留。
3. Bytes 覆盖非 UTF-8、选区内 NUL 后补零、选区前 NUL 不影响、65,536 字节边界和超限；长度保持选区长度。
4. Array 结果顶层修改与源隔离、嵌套修改共享；选中失效 Object 在源与结果均为 Undefined，未选中及嵌套失效 Object 保留；新空数组身份差异单列。
5. 内部借用冲突和资源失败无部分源更新；数组深度边界、重复共享子图及现有无环约束继续有效。
6. 单步/连续运行结果一致、零预算不变；跨对象及继承调用返回后上下文正确；范围错误即使位于 catch 内仍终止且不污染之后的数值来源。
7. 初始化与默认表达式中的 `45` 仍显式拒绝，构造/回滚辅助函数不能绕过生命周期检查；非法模式拒绝，par8 非零不改变普通函数的范围结果。
