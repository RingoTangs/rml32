# 方法与复现

在仓库根执行：

```sh
python3 -B docs/stage2bk-combination-audit/verify_validation.py --write
python3 -B docs/stage2bk-combination-audit/verify_validation.py
```

第一条实际运行所有验证，只改写本批产物；第二条只读重算来源边界、观察比较和收据哈希。Cargo 使用 locked/offline，不安装工具链或拉取镜像。最终日志包含逐命令 argv、退出码、stdout 和 stderr；子回放另保存压缩逐行观察。参考 ELF 与 2AW 语料结果只核对冻结哈希，未重新执行。

## 基线

`baseline-inputs.json` 记录 2BJ 收据覆盖的 1,096 个文件。`baseline-overlay.json.gz` 保存相对提交 `0c4fbf40007d0bc2f877a269ba6e1ca22ef6fcc0` 的 53 个文件；新建 detached 副本后应用覆盖层、恢复哈希确认的 CRLF，逐文件核验后才运行历史验证。此方法不依赖当时未提交或已暂存的状态。历史 497 项为 2BJ 当前校验器 32 项加其递归固定版本的 465 项，不在当前源码上强行运行历史收据检查。

## 批处理模型

输入仅含动作、配额、布局与逻辑标签。六种布局为独立双复制、同源双目的、同目的同值、同目的冲突、复制写入移动源、独立双移动。每种布局枚举长度 0—2 的六字母干扰词：改写 s0/s1/d0/d1、退役无关 Host 根、零预算维护；以 commit 或 abort 结束，共 `163 × 6 × (1+6+36) × 2 = 84,108` 条。准备失败停止该 trace，终止后释放原控制块并检查 Weak。布局摘要的 rejected 只统计 commit/abort 终结动作；same_conflict 在 prepare 阶段拒绝，其 9,374 次拒绝计入全局 rejected，可从逐行观察复算。

Rust 使用真实 CopyPlan 的 copy/write/transfer，不沿用 2BJ 标量预留场景的特殊映射；观察读取真实稳定槽、对象 ordinary、数组 header owner、根退役和队列计数，连续两次观察必须相等。标量区分 Int(1) 与 Undefined；实际对象和头 identity 映射到 o0/h0。初始数组含一个无所有权的 Undefined 成员，抽象模型无需为它增加语义 Owner；weak 元数据条目不作抽象行数等价宣称。

新 `batch_oracle.py` 维护独立 watch set、待发布值和移动集合，复用冻结 2BH 的配额、释放和审计原语。准备阶段记录快照与版本，不把延迟到提交的 Owner 获取提前计入；提交先核验所有版本和源冲突，再在候选状态按去重目的集合一次 charge 总峰值，最后发布。失败不替换原模型；同值重复目的只收费一次，raw move 不添加 retain。当前布局的目的原值为 Undefined，没有将此参考层声称为任意混合图重写的完整模型。

检查器逐行核对 before/after、错误类别及跨动作连续性；丢行、乱序、多行、错误身份、计数和部分发布必须拒绝。批处理不执行 metadata 扫描；维护参考模型保持 2BJ 原样，由旧核心回放复核。

## Mapping 与公开镜像

共享合成夹具在正常库集成驱动与内部驱动分别编译。每个配额配置交叉运行新输出/三元素数组复用、live Object/失效 Object/含 Object 数组、第一/第二轮目标、普通/catch 包装，合计 3,912 条；正常库不使用故障注入或私有工厂。内部仅在目标单步增加 reserve 调用计数，公共投影必须相等。

完整成功有 24 条，均属于显式成功对照配置；其余 3,888 条分别在 setup/start/prefix 分类为 Limit，未到达目标，不声称逐项配额阈值等价。每个成功场景记录目标调用数 C，注入全部 `0..C-1`，并以 C 作不失败边界对照：共 1,130 次注入拒绝与 24 次对照。失败必须保持栈、复用输出及 Mapping 源成员，后续 run 返回同一错误，不能重放；第二轮夹具也因此保留第一轮已提交结果。成功检查 key、ordinal、payload、输出身份/别名和最终帧深度；catch 包装在循环结束后触发已知数值错误检查展开。

公开镜像是公共可观察投影，不声称直接读取内部 ordinary/exec、私有循环 cursor 或全部元数据。实际源、输出和 VM 行为由 Rust 断言核对，Python 独立检查投影、payload 分类与失败点边界。

## 关闭不变量

排队状态预先通过真实 VM 将两个对象入队；active 状态保留一个 pending 对象的执行帧。交叉两种状态、零/各一单位预算、两个根释放与关闭的 12 个合法排列（维护发生在关闭前），共 7,824 条。5,184 条因对象配额不足在 setup 拒绝，2,640 条完成全部动作。

独立规则要求排队状态的单位维护恰好排空一个对象、余一个队列责任；active 状态不提前清理执行对象；根退役为零，metadata 单位精确为给定预算，stop 为 BudgetExhausted。关闭后剩余根的 retain/snapshot 必须拒绝，原 Registry 与 ctx 的 Weak 在最后一个根释放后失效。观察闭包只保存 Weak，读取时不持久保活。借用导致的延迟退役、回调持根环及外部最后一个根另有普通 Rust 回归。

## 边界与验证

旧八个驱动通过冻结 runner 的 run 函数重新执行，产物封装到本批，不使用旧目录的 --write。旧 2,592 条核心和 972 条公开矩阵均按 debug/release 重跑；六个更早驱动按其既有协议运行。39 项模型和 112 行算术单独重新执行。新的 28 项 Python 测试覆盖生成域、反例污染、独立峰值/移动规则、关闭存活、失败点及命令/测试/收据缺失。

没有新的生产偏差或生产修复；`verify_boundary.py` 要求本批 Rust 改动在去除 cfg(test) 后与封存基线 token 完全相等，并保留改动模块中的 16 个旧测试函数体。更大图、任意长事务、任意多目的提交和原生退出行为不在本批等价范围内。
