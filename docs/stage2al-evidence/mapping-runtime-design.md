# 2AL：下一批受限 Mapping997 实施规格

这是尚未实施的 Rust 设计。依据 `../vm-mapping-iteration-semantics.md`、本目录 findings F01–F14 和源码审计；本轮不改 API 或运行时。首批目标是普通函数 Int/Bytes键、attrib=1的 Mapping997；保留当前初始化/构造任务、成员/临时绑定、控制槽别名及默认表达式限制。

## 容器存储与顺序

在现有 MappingData 内增加私有桶链拓扑，桶中存稳定节点标识；节点拥有键和既有 `Rc<Cell>`。BTreeMap仅作等键查找索引，不决定遍历次序；`entries()` 保留当前插入位置顺序及浅快照行为。覆盖只改值，不改节点位置/Cell；扩容仅重接桶链，不替换成员Cell。owner销毁清理成员的现有契约不变。

使用制品中的256字节表及F01/F02算法；Bytes始终按内容计算，不引入原生shared头或公开缓存属性。哈希到首NUL/32字节，相等按全长；Int转i32后算术右移4位并与u32 mask相与。新键头插、空桶预算及grow完全按F04–F06，不能用标准HashMap或插入顺序模拟。

构造器以去重前输入pair数作容量hint，按既有公开构造器顺序插入；VM `18` 继续逆转栈顺序后调用构造器。初始化hint<=8为8，否则为严格更大的2次幂。现有65,536项及深度64限制继续生效；桶数不是项数，hint=65,536会需要131,072桶，不能新增同数值桶上限造成误拒绝。检查尺寸并可控分配，失败不部分增加count、entries、index或桶链。

缺失键的成员引用仍创建Undefined并头插到原生桶链；覆盖和resize保留已取得引用的Cell身份。本批不新增公开删除/清空接口或真实efun。删除成功路径由离线模型和案例固定；删除后成员引用的寿命及回收链属于后续证据门槛，不能顺带开放。

## 循环与结果数组

私有 LoopState 增加 `Mapping { owner, bucket, subindex, ordinal }`；三个计数初值0。每条12/50从owner当前桶链重扫，不保存节点游标、元素快照或mutation版本。准确复现F08跨桶时的存储subindex=1、耗尽计数推进，以及F09修改/扩容的结果。subindex和ordinal用wrapping_u32；旧subindex按i32解释，只有正数才跳过节点（原生TEST/JG），ordinal输出按i32载荷解释。预算暂停不推进，实际执行一次只检查一次。

每次有效输出重新读取绑定槽：当前是三元素Array则复用同一header和三个Cell，否则创建Array3。依次准备key/value的现有copy_value结果和ordinal。不得在LoopState缓存首个输出数组；绑到另一Array3后必须改写新数组。空集合/耗尽保留绑定，owner重绑不改变来源；不增加公开Value变体。

保持既有Value复制及死对象/函数上下文规范化策略，允许现有已支持值，只在能保持无环/深度限制时生成三元数组。选定输出数组若与源Mapping的值图交叉可达，或与控制/绑定/待写槽产生无法安全去重的Cell冲突，首批在写入前返回UnsupportedFeature；不模拟未闭合的原生cleanup/copy别名次序。可安全复用的普通独立数组别名必须支持，不能以共享引用数>1为由复制数组。

## 原子提交、诊断与接口

先计算下一游标、跳转、输出、规范化及分配，再验证绑定可写、图约束和全部借用，最后以现有批量Cell替换提交控制槽、绑定/输出成员及必要源更新。不要在克隆LoopControl后提前改共享数组。重复Cell拒绝或预检，不采用隐式末次覆盖。旧值在所有RefMut释放后销毁。

资源/借用失败不改变数据或游标；沿用Limit/InvalidState/UnsupportedFeature及现有类型错误分类，不新增RuntimeFaultSite或通用catch来源。派发前内部PC已递增，失败不回滚；公开诊断仍指向原指令，终止状态沿用既有策略。这是Rust安全契约，不是原生OOM回滚证明。

无需公开API、依赖、操作码或参数格式变化。更新限定能力说明与测试即可；75种支持/73种交集保持不变，G05仍标partial，不能因Mapping997首批通过而关闭全部Mapping门槛。
