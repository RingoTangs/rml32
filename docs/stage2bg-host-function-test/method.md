# Acceptance method and limits

The baseline contains 950 files. Boundary, object, VM and lifecycle runtime allow test hooks; README/roadmap permit only a prefix preserving their complete historical suffix. The other 944 files remain byte-identical, including the reference ELF, preparation code, adapter, prior fixtures, models, native evidence and receipts. New fixtures are reachable only through cfg(test).

The fail-closed source projector compares boundary/object/VM production tokens to the pinned baseline, removing only supported cfg items and expanding four established exact factories. Runtime remains inside the frozen test-only adapter gate. Original ordinary test bodies, both compile-fail doctest bodies and all 785 scenario names are preserved. Shifted doctest source lines are normalized only for identity comparison. Actual non-test debug/release builds supplement this limited scanner; it is not a general compiler proof.

Thirty-four new ordinary Rust scenarios cover actual prepared creation/invocation, creator and caller distinctions, scalar bits, unique/shared Array/Mapping captures, nested Function members, callback retain and results, binding replacement, quota edges, missing registration, invalid creators, foreign origins, profile/type/cycle rejection, allocation/borrow/workspace failure, negative audits, task-parameter ownership, extraction/rebuild and close cycles. Successful cases use real preparation; direct invalid capture fixtures are not used as positive evidence. Six ignored replay workers execute separately.

callable_diff.py declares fourteen timelines and 120 checkpoints independently of Rust output. Each checkpoint compares actual object states, refs, execs, cleanup flags, queue and record residency; actual frame ID/body/object; observed head owner count, creator and capture contents; graph root owner count; Registry root count, callback count and closed state. Diagnostic Function views add no semantic owner. Every case checks actual Object records, FunctionData, container counter, Registry and StoreState Weak probes expire after teardown.

Four scalar traces crosscheck common generic head/creator/frame ownership events with the frozen 2BA World: unique zero/scalar invocation, shared retain/invocation and pending creator exit/drain. The model does not resolve Host slots or callbacks. Global context, containers, errors, bindings and physical storage use separately declared golden expectations plus real audits. No fake Host frame, new exhaustive state domain, complete Host model or native timing equivalence is claimed.

Per-trace bounds are two Objects, two heads, two containers, three installed frames, sixteen owning slots, eight Host roots and at most one thousand requested instructions. Rich nested graphs and the 127/128 argument boundary are additional unit evidence, outside the small timeline domain. The trace set uses at most one head and one container, staying within these declared caps.

All five previous drivers rerun unchanged: 13 managed traces/85 checkpoints, 12 Host traces/75 checkpoints, 10 VM traces/70 checkpoints, 18 adapter traces/146 steps and 14,948 attempted kernel transitions. Their old reports and generators remain frozen; this directory stores new actual logs and current-source hashes.

Historical validation runs 2BF's 26 Python checks and read-only receipt in a local shared clone at 1927505. Its unchanged historical.run() reexecutes the prior 340 checks under pinned 891f55b, d237bf3, 1306a9b and 7a21530 authorities. Total: 366 historical checks, explicitly not current-source checks. Verified legacy CRLF bytes are restored only in temporary clones after normalized-content equality; no old verifier is relaxed.

Full receipt generation records actual argv/status/stdout/stderr for historical checks, both Rust test/build profiles, fmt, strict clippy, all six replay workers, current source checks and current Python tests. Artifact hashes cover the permitted edits and complete delivery. The frozen 2AW corpus result is reused by exact hash with rerun=false. No reference executable, business bytecode, network service or new native analysis is run; twenty native unknowns are not promoted.
