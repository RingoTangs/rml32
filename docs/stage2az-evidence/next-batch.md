目标是连接错误后仍可被恢复代码使用的 H/A 副本，与 H/A free 及适用 creator unref。现有 C 栈／寄存器保存、topEnv 的 funCp/catchLevel、扩展页根和 allocator shutdown 只闭合各自接点，见 [R01](r01-paths.md) 和 [处置表](allocation-disposition.json)。

下一次静态补查只在出现具体新增读写边、地址逃逸或恢复字段时进行，并记录来源、目标和覆盖范围。对于导入恢复实现、未解析别名和外部根，先说明缺少哪段实际制品或观测，不能以重复导出同一 helper 代替证据。只证明页 free 时继续保留语义释放未知。

如果没有新的静态接点，下一次规划应先确定：目标兼容范围是否要求此原生错误路径的最终清理等价。要求等价时，再选择针对该恢复关系的证据方案；允许保持 Rust 发布前预检差异时，应先形成明确差异规格。原程序动态对照和 D01 设计都不属于本批交付，当前不自行启动。

## R02 后续只按实际依赖扩展

已知六个 caller 的相邻持有、失败回退和三类 callback，以及 `_vmInits` 的注册／消费者分类已交付，见 [R02](r02-classification.md)。只有某条拟支持路径依赖队列消费、callback 退出、实际停机调用者或后继安全点时，才沿该具体关系补查。
