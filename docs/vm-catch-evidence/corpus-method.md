# Catch 指令只读语料核对

输入复用 `docs/compatibility-evidence/programs.json.gz`，覆盖主版 Magic559 ABI 的 7,159 个已解析程序、101,592 个普通函数和 6,474,773 条指令；初始化段和隐藏函数也扫描，本语料隐藏函数为 0。旧认证格式及已知 DBA 解压失败成员不在成功解析范围内。输入三个文件的 SHA-256 写入生成报告。

```sh
python3 docs/vm-catch-evidence/analyze_corpus.py
python3 -m unittest discover -s docs/vm-catch-evidence -p test_analyze_corpus.py
```

默认复算并逐字比较两个 JSON；只有 `--write` 更新生成文件。脚本只用 Python 标准库读取保留的解码快照，不执行 ELF、业务字节码或启动脚本。目标公式由 Ghidra 原生证据确认：`vm_newThreadCatch@0x080aaf84`（Evidence ID `ev_446aa83f597882387e0856507a84ad5ec466a2e91a4e234c7e9c000ca98eec9a`）保存 `current.ip + offset`，而 `regularProcessor` 在分派前递增 ip 并对 par16 作符号扩展，因此解释执行模式目标为 `pc + 1 + signed(a)`。区间配对和路径类别仍只是词法候选。

## 已观察到的静态结构

- `0x2c`、`0x1a`、`0x0e` 各出现 3,266 次，全部位于普通函数，共 2,495 个代码段包含 `0x2c`。
- `0x1a` 和 `0x0e` 操作数全部为 `(0,0)`；`0x2c` 有 64 种原始 `(i16 a,i8 b)` 组合，精确直方图见 `corpus-summary.json`。
- 按原生确认的 `pc + 1 + signed(a)` 公式，3,266 个目标均在段内并指向 `0x0e`，目标前两条节点均为 `0x1a`、`0x1f`。这不是通过执行验证的路径可达性。
- 对每个向前候选区间 `[start_pc+1,target_pc)` 独立扫描：3,266 个含 `0x1a`；3,262 个含调用类 `05..09`；820 个含跨对象调用 `08`；21 个含循环 `12/23/50`；11 个含返回 `48/49`，且返回在第一个词法 `1a` 之前；3 个含另一 `2c`。
- 候选半开区间 `[start_pc,target_pc)` 的最大重叠数为 2。这只是词法区间重叠，不证明运行时同时存在两个活动捕获上下文。

每项区间统计以“含至少一条”为单位，同一个外层区间可能包括内层区间的节点，类别可以重叠，不应相加为互斥总量。特别是“返回在 end 前”不证明返回可达；调用节点也不证明调用成功或被捕获。

## 定位、示例与限制

`corpus-examples.json` 按最短代码段、来源、函数名和 PC 选取确定性代表样本，记录成员 SHA-256、函数索引、原始节点、候选目标和小窗口。类别样本附对应节点的 `witness_pc`/窗口，以及目标附近窗口。所有字节偏移均相对于**解压后的成员**，不是 ELF 地址或压缩包物理偏移；段内 PC 是节点序号，每节点 4 字节。

本工具不执行 CFG 可达性、栈值传播、错误分类、动态函数指针解析或跨函数异常配对。因此不会把词法 `1a` 直接配成动态 pop，也不会从数量相等推导栈平衡、编译器普遍保证或运行时正确性。负/越界候选目标及畸形或截断节点被显式报告；畸形段整体跳过语义扫描，主语料验证要求错误为 0。九项独立合成测试覆盖空输入、嵌套区间、双向越界、截断与宽度错误、循环/调用分类、非向前目标、初始化段和无 start 的 end。
