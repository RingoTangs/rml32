# Acceptance method and limits

The pinned baseline has 921 files. Four sources allow test hooks: boundary, object, VM and lifecycle runtime. README/roadmap allow a prefix preserving the complete old suffix. The other 915 files remain byte-identical, including the reference ELF, preparation code, adapter, old Rust fixtures, models, native evidence and receipts. The new Rust fixture is gated by cfg(test).

The frozen fail-closed source projector compares production token streams for boundary/object/VM to the baseline, removing only supported cfg items and expanding the four established exact factories. Runtime remains reachable only through the frozen test-only adapter module. Legacy ordinary test bodies and the 759 baseline scenario names are preserved. The scanner is not a general compiler proof; actual non-test builds run in debug/release.

Twenty-six new ordinary Rust scenarios cover actual prepared programs through the checked boundary: three-layer initialization/create/reverse rollback, omitted lifecycle functions, nested helper frames, limits and injected workspace/Cell failures, source diagnostics, pending deletion, parameter graph lifetime, cancellation/extraction/close in each phase, borrowed drain retry, self-reference cleanup, and negative ownership audits. The original two compile-fail doctest bodies and identities remain; source line offsets may shift. Five ignored replay workers are separately executed.

managed_diff.py declares thirteen minimal synthetic program timelines with eighty-five checkpoints. Expected states are declared independently of Rust output. Checkpoints compare object states/refs/execs/cleanup flags, queue, physical record residency, actual task phase/cursor/constitution, frame ID/body/object, parameter header owners, primary and rollback errors, closed state and Registry root count. Every trace verifies final record, parameter counter, Registry and StoreState Weak probes expire.

Bounds are two Objects, three constitutions, three installed frames, sixteen projected owning slots, eight Host roots and at most one thousand requested instructions per trace. The traces do not constitute exhaustive managed-task exploration. Rich shared writes, Function/container roots and borrowed cleanup cases are additional unit evidence rather than part of the minimal timeline domain.

Three shared traces crosscheck common object/frame events with the frozen 2BA World: initialization handoff, successful construction and positive-budget cancellation after pending deletion. Managed metadata is outside that model. The other golden timelines explicitly test Rust task policy. In particular, zero-exec deferred cleanup is not represented by adding a fake model frame or changing the old model's delete behavior. No full native equivalence or universal cleanup progress is claimed.

All four old drivers rerun: twelve Host traces/75 checkpoints, ten VM traces/70 checkpoints, eighteen adapter traces/146 steps and 14,948 attempted kernel transitions. Original generators and reports remain frozen; only this directory receives new actual reports/logs and current-source hashes.

Historical validation uses a local shared clone at 891f55b: its 24 Python checks and read-only 2BE receipt run there. Its unchanged historical.run() reruns the prior 316 checks under their own pinned d237bf3, 1306a9b and 7a21530 authorities. Total: 340 historical checks, never advertised as current-source tests. Verified legacy CRLF bytes are restored only inside temporary clones after normalized-content equality checks; no old verifier is relaxed.

The receipt captures actual argv, exit status and stdout/stderr for historical validation, Rust tests/builds in both profiles, fmt, strict clippy, all five replay workers, current source checks and new Python checks. Artifact hashes cover permitted edits and the complete new delivery. The frozen 2AW corpus result is reused by exact hash with rerun=false. No reference executable, business bytecode, network service or new native analysis is run.
