# 默认与可变参数语料统计方法

## 输入与复现

此目录脚本只静态解析数据，绝不执行 ELF、启动脚本或 VM 指令。输入是既有 7,159 个解码程序、PAK 成员目录、原始输入清单，以及阶段 2G 已精确解析的调用记录。每次核验还直接读取原始 PAK / `.o` 成员，核对包 SHA、成员 SHA 和参数描述符字段。

```sh
python3 docs/vm-optional-arguments-evidence/test_verify_optional.py
python3 docs/vm-optional-arguments-evidence/verify_optional.py
```

默认命令只读重算，比较完整确定性 gzip 字节及摘要。`--write` 仅生成本目录的 `optional.json.gz` 和 `summary.json`；gzip 的 mtime 固定为零。脚本仅依赖 Python 标准库，导入既有静态解压模块时禁用字节码缓存，不调用其写出入口。

## 字段与地址证据

20 字节参数记录的 `+0x0a` 是 little-endian signed16 `defaultActionNum`：`vm_checkArgNum` 的 `0x080953c4` 使用 MOVSX 读取；`0x080953bc` 读取 `+8` 参数编号，`0x080953cb` 累加默认指令数量，`0x080953d9` 更新 IP。证据为阶段 2G 的 `ev_d17aa0d7a395baf8b760f4dd773008e55d6a7fc1e8c6931a9657f73663982946`。

加载证据 `vm_loadFun@0x080959b8`，`ev_b513e6242f5447517c22636c5c877a93b397b974851b7928f195106d957a1079`：读取完整 0x14 字节记录，重置名称和运行时指针，但保留 `+0x0a`。

脚本将首指令 `0f` 后的 PC 记为 1。`argc < max` 的目标是 `1 + sum(defaultActionNum where index < argc)`；`argc >= max` 的目标是 `1 + entry.a`。对每个 `argc ∈ [min,max]` 保存目标；顺序默认表达式区间使用半开区间。所有偏移均为解压成员内偏移，不是 ELF 地址或压缩包物理偏移。

## 分类与限制

- `min == max` / `min != max` 只表示原始参数范围；不能据此单独判断“固定 / 默认 / 可变”的原生可调用性。
- 函数属性低两位完整保留。引用参数按 flag bit0 统计；不推断实参栈来源。
- 调用统计复用阶段 2G 的单 constitution、无继承、唯一索引解析。global、多 constitution、动态目标仍不解析；argc 仅是 `b & 0x3f`。
- `entry.a == sum(defaultActionNum)` 是比较项而非合法性断言：非零默认初始化还包含结束指令，需结合原生 `47` 语义解释。真实语料中的差异保留，不做修正。
- 所有出现次数都是静态序列化节点数量，不代表执行次数、可达性、源码唯一函数数或 Rust 支持覆盖率。

## 合成测试

测试覆盖固定、部分缺省、全部可选、超额及不足参数、保留可变属性与引用组合、默认区间为零/负数/越界、入口总长度差异，以及已确认的默认入口目标计算。测试只构造元数据，不解释执行指令。

## 本次语料结果

101,592 个函数中，90,961 个原始 min/max 相等，10,631 个不等；后者包含 1,822 个有显式默认表达式及 8,809 个零默认长度函数。8,920 个参数描述符数量不同于 max 的函数全部没有代码，且 min=max=0，因此不能把该差异视为可执行函数格式错误。

87,774 个首指令为 `0f` 的函数全部符合入口布局：非零默认表达式后为 `47` 再 `1b`，零默认表达式则直接 `1b`。有显式默认表达式的函数 entry.a 全部等于长度和加一，其余等于零。没有负默认长度、累计默认区间越界或合法 argc 范围内的入口目标越界。

这些 min/max 字节在原生 `0x080952fd`、`0x0809530c` 使用 MOVSX 按有符号8位读取；脚本保留语料原始非负表示并单独检查最高位。实际最大 min=19、max=21，没有最高位置位样本。可变参数属性 bit0 的入口检查在 `0x08095325`，不表示参数自动打包成数组。

默认表达式的直接指令中，31 个函数含调用，没有 `37`/`39`；这不排除被调函数访问其他状态。1,219 个函数的允许 argc 区间涉及省略引用形参；所有零默认长度省略形参的类型均为 mixed。没有观察到零默认 mixed 空洞位于后续默认表达式之前。这些是语料观察，不是语言层禁止该组合的证明。

DWARF `/DWARF/vm_fun.h/Vm_Fun_Arg` 大小20及字段 offset10/size2 的证据为 `ev_3a2145a4ec5bf063ceb5de533653f40d5ce70cd826ccb17d03b9892fc915df74`。生成器与重排函数证据分别为 `ev_2c27ff7488e9819ae0c431411d6590807eaddf4a9037881bcf3d3e67b56ca294` 和 `ev_999d6b2ce2163dabf3dfe97c69fc89bbf621502b7efc62e552dbaefa85dda75e`，见本阶段 REA 导出。脚本保存逐 argc 入口目标、遗漏形参及默认操作码分布，供后续实现界定支持范围。

## 可变参数与空声明交叉核验

带 attrib bit0 的函数共105：71个有代码（46个属性低两位为1、25个为3），34个空代码（33个低两位为1、1个为3）。因此排除 atomic 后的可执行可变参数函数候选为46，而不是105。

精确解析调用中603个 argc 超过原始 max：590个非可变调用全部指向空代码定义；13个可变调用中7个指向有代码定义、6个指向空代码定义。故不能将这603次静态比较直接称为“非法超额调用”。摘要 `resolved_call_code_shapes` 单独保存这些分类。
