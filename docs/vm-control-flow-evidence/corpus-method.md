# 六条控制流指令的只读语料核对

输入是既有 `docs/compatibility-evidence/programs.json.gz`，包含主版 Magic559 ABI 的7,159个已解析程序、101,592个普通函数和0个隐藏函数。初始化段仍逐一扫描；本语料中的六条目标指令全部位于普通函数。旧认证格式不在此输入中，已知DBA解压失败成员也不伪装成成功解析程序。

```sh
python3 docs/vm-control-flow-evidence/analyze_corpus.py
python3 -m unittest discover -s docs/vm-control-flow-evidence -p test_analyze_corpus.py
```

默认仅复算并逐字比较现存JSON；`--write` 显式更新两个生成文件。脚本使用Python标准库，不加载业务模块，不执行字节码，不运行目标ELF，也不读取/启动服务脚本。输入哈希写入生成报告。

`corpus-summary.json` 保存全部六条指令的精确原始操作数组合直方图（键为有符号 `a,b`）、解码组合种类数和前20种组合。每条节点为 `(i16 a, i8 b, u8 opcode)`；0a/0b按原生调度的符号扩展表达式 `(b << 16) | a` 访问同一段metadata，再解码两个小端有符号i32。元数据边界独立检查。不得将负a按u16拼接。

`examples.json` 为每条指令选取含该指令的最短代码段（并列按来源与PC排序），提供五节点以内窗口、原始/解码操作数、成员SHA-256及节点/元数据在解压后成员内的字节偏移。这些偏移不是ELF虚拟地址，也不是压缩包物理偏移。函数名仅用于定位，不能证明运行时调用。

统计次数与既有 `compatibility-summary.json` 逐项比较，全部节点数也必须相同。静态次数不代表执行频率、路径可达性或功能覆盖率。关于原生类型、栈效果、目标计算基准及清理规则，以本阶段Ghidra证据与主报告为准。

本阶段Ghidra确认后，脚本还检查五条分支指令：所有taken目标统一为 `pc + 1 + delta`，0a/0b的delta来自metadata第一个i32，0c/12/50来自a；23不跳转。共核对83,557个目标、20,643个非空字符串池索引（0b第二个i32），以及62,550个循环变量槽（23取a，12/50取b，范围 `-local_count <= slot < max_args`），错误数均为0。该检查只证明单个静态位置合法，不证明路径可达、循环配对或运行时槽类型正确。

23之前的直接相邻节点全部为pushShortNumber（3b）：模式-1出现38次，+1出现4,380次，997（0x3e5）出现16,432次。这里只报告实际邻接结构，不从邻接替代栈分析；997的含义由原生函数证据说明。当前普通函数中负槽范围检查通过，不等于槽始终持有正确的循环状态。
